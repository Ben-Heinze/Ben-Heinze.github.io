───── page 3/14 ─────

Resource ownership and execution are distinct responsibilities
that can be managed separately.

Modern operating systems treat them independently.

Conceptual Separation: Resource ownership is about what a
process possesses (e.g., memory, files), while
scheduling/execution is about what a process does (e.g., running
its code).

A process can own resources without executing (e.g., a blocked
process holding a file lock) or execute without owning significant
resources (e.g., a lightweight computation).

───── page 4/14 ─────
Implications

This independence allows the OS to manage resources and
execution separately. For example:

Resource Management: The OS can allocate/deallocate resources
(e.g., memory or I/O devices) independently of whether the
process is currently running.

Scheduling: The OS can prioritize, and dispatch processes based
on their execution state and priority, regardless of their resource
holdings.

───── page 13/14 ─────
Threads

In an OS that supports threads, scheduling and dispatching is
done on a thread basis.

Most of the state information dealing with execution is maintained
in thread-level data structures.

Suspending a process involves suspending all threads of the process.

Termination of a process terminates all threads within the process.

The Sequential File

Records are stored in order of a
designated key field.

In the traditional model, records
have a fixed format, and the key
uniquely identifies each record.

Well suited to batch processing,
where many or all records are
processed in sequence.

Can be stored on disk or tape;
sequential access is especially
well suited to tape.

Without an auxiliary index, finding
a particular record generally
requires a sequential search.

───── page 18/48 ─────
The Sequential File

Works very well if you must process all the records in the file.

Typically, a sequential file is stored in simple sequential ordering of
the records within blocks.

That is, the physical organization of the file on tape or disk directly
matches the logical organization of the file.

For interactive applications that involve queries and/or updates of
individual records, the sequential file provides poor performance.

Access requires the sequential search of the file for a key match.

If the entire file, or a large portion of the file, can be brought into main
memory at one time, more efficient search techniques are possible.

───── page 19/48 ─────
The Sequential File


sequential files, when we try to insert a record, it becomes harder to


Typically, a separate
pile file

maintained for inserting new records.

The periodically batch update is performed to merge the
separate file in the master file to produce correct key sequence.

───── page 21/48 ─────
Indexed sequential file

Index is a simply a simple sequential file.

Each record in the index file consists two things.

Key field

Pointer into the main file.

To find a specific field value, index file is searched sequentially to
find the highest key value that is equal or precedes the desired key
value.

Then we read that pointer value and start searching the main file
from that point onwards.

───── page 22/48 ─────
Indexed sequential file

Suppose you have a sequential file with 1 million records.

To search for a particular key, on average, it will require half a
million record accesses.

Now suppose you have an index with 1000 entries, with keys in the
index evenly distributed over the main file.

Now it will take on average 500 accesses to search over the index
and 500 accesses to main file to find the record.

Average search length is reduced from 500000 to 1000.

───── page 23/48 ─────
Indexed sequential file

The indexed sequential file greatly reduces the time required to
access a single record, without sacrificing the sequential nature
of the file.

We can even add multiple levels of indexing for greater efficiency.

Chained Free Portions

The free portions may be chained together by using a pointer and
length value in each free portion

Negligible space overhead because there is no need for a disk
allocation table

Suited to all file allocation methods
Disadvantages:
A

A

recover the pointer to the new first free block before writing data
to that block

───── page 47/48 ─────
Indexing

Treats free space as a file and uses an index table as it would for
file allocation.

There is one entry in the table for every free portion on the disk.

For efficiency, the index should be on the basis of variable-size
portions rather than blocks

This approach provides efficient support for all of the file
allocation methods

* Gradient Descent

Three types of gradient descents:
- Batch gradient descent
- Incremental (stochastic) gradient descent: 
- Mini-batch (stochastic) gradient descent:# Three Types of Gradient Descent

**Setup.** Training set $D=\{(x^{(i)},y^{(i)})\}_{i=1}^{n}$, parameters $\theta$, per-example loss $L^{(i)}(\theta)$, and total cost

$$J(\theta)=\frac{1}{n}\sum_{i=1}^{n}L^{(i)}(\theta)$$

All three methods use the same update rule $\theta \leftarrow \theta - \alpha\,\hat{g}$  they differ **only in how much data is used to estimate the gradient $\hat g$ before each update.**

---

## 1. Batch Gradient Descent ("full batch")

Use **all $n$ examples** to compute one exact gradient, then make **one** update.

$$\theta_j \leftarrow \theta_j - \alpha \frac{1}{n}\sum_{i=1}^{n}\frac{\partial L^{(i)}(\theta)}{\partial \theta_j}$$

For linear regression with squared error this is the familiar LMS form:
$$\theta_j \leftarrow \theta_j + \alpha\sum_{i=1}^{n}\big(y^{(i)}-h_\theta(x^{(i)})\big)x_j^{(i)}$$

**Repeat until convergence** { one sweep over data  one update }

| Pros                                            | Cons                                                       |                                                                    |
|-------------------------------------------------+------------------------------------------------------------+--------------------------------------------------------------------|
| Exact (unbiased, noise-free) gradient           | One update costs a full pass over data local min otherwise | Can get stuck in poor local minima / plateaus (no noise to escape) |
| Easy to vectorize; deterministic & reproducible | Cannot learn online (new data arriving)                    |                                                                    |

---

## 2. Incremental / Stochastic Gradient Descent (SGD)

Update after **every single example**.

```
Loop (epoch):
    shuffle D
    for i = 1 to n:
             L()
```

For linear regression: $\theta_j \leftarrow \theta_j + \alpha\big(y^{(i)}-h_\theta(x^{(i)})\big)x_j^{(i)}$

Key idea: $\nabla L^{(i)}(\theta)$ is a **noisy but unbiased** estimate of $\nabla J(\theta)$, i.e. $\mathbb{E}_i[\nabla L^{(i)}]=\nabla J$.

| Pros                                                             | Cons                                                                                              |
|------------------------------------------------------------------+---------------------------------------------------------------------------------------------------|
| $n$ updates per epoch  progress is much faster, especially early | Gradient is noisy: $J$ fluctuates, path "zig-zags"                                                |
| Scales to huge / streaming data; true **online learning**        | Never settles exactly at the minimum  oscillates in a region around it unless $\alpha$ is decayed |
| Noise helps escape shallow local minima / saddle points          | Poor hardware utilization (no vectorization over examples)                                        |
| Low memory (one example at a time)                               | Sensitive to example ordering  must shuffle                                                       |

**Convergence condition (RobbinsMonro):** decaying step sizes with
$$\sum_t \alpha_t=\infty,\qquad \sum_t \alpha_t^2<\infty \quad\text{(e.g. } \alpha_t = \tfrac{c}{t_0+t}\text{)}$$
guarantee convergence (a.s.) for convex problems.

---

## 3. Mini-Batch (Stochastic) Gradient Descent

Compromise: use a random subset $B$ of size $b$ (typically $b = 32, 64, 128, 256$).

$$\theta \leftarrow \theta - \alpha\,\frac{1}{b}\sum_{i\in B}\nabla L^{(i)}(\theta)$$

```
Loop (epoch):
    shuffle D, split into n/b mini-batches
    for each mini-batch B:
              (1/b) _{iB} L()
```

- Gradient variance shrinks like $1/b$  smoother than pure SGD, noisier than batch.
- Matrixmatrix operations  excellent **vectorization / GPU** efficiency.
- $b=1$ recovers SGD; $b=n$ recovers batch GD.
- Rule of thumb: if you scale $b$ up by $k$, scale $\alpha$ up by $\approx k$ (or $\sqrt{k}$).
- **This is the default in modern machine learning / deep lear 









Tell me about naive baye## Core idea

Naive Bayes is a family of probabilistic classifiers built on Bayes' theorem plus one strong simplifying assumption. Given features $x_1, \dots, x_n$ and a class $y$:

$$P(y \mid x_1,\dots,x_n) = \frac{P(y) \, P(x_1,\dots,x_n \mid y)}{P(x_1,\dots,x_n)}$$

The hard part is $P(x_1,\dots,x_n \mid y)$  modeling the joint distribution of all features requires exponentially much data. The "naive" assumption is that features are **conditionally independent given the class**:

$$P(x_1,\dots,x_n \mid y) = \prod_{i=1}^{n} P(x_i \mid y)$$

Now you only need to estimate $n$ simple one-dimensional distributions per class. The classifier becomes:

$$\hat{y} = \arg\max_y \; P(y) \prod_{i=1}^{n} P(x_i \mid y)$$

(The denominator is dropped since it's constant across classes.)

## Why it works despite being wrong

The independence assumption is almost always false  in text, "New" and "York" are obviously correlated. But Naive Bayes often classifies well anyway, because it only needs the *argmax* to be correct, not the probabilities. Correlated features skew the magnitude of the posterior badly (NB is notoriously overconfident, pushing probabilities toward 0 or 1) while frequently preserving the ranking of classes. Domingos & Pazzani's 1997 paper is the classic analysis of this.

## Main variants

| Variant | Feature model | Typical use |
|---|---|---|
| **Multinomial** | Word/token counts | Text classification |
| **Bernoulli** | Binary presence/absence | Short texts, when absence is informative |
| **Gaussian** | $P(x_i \mid y) \sim \mathcal{N}(\mu_{iy}, \sigma_{iy}^2)$ | Continuous features |
| **Complement** | Fits to the complement of each class | Imbalanced text data |
| **Categorical** | Discrete unordered features | Mixed tabular data |

## Practical essentials

**Laplace / additive smoothing.** If a word never appeared with a class in training, $P(x_i \mid y) = 0$ zeroes out the whole product. Fix by adding a pseudocount $\alpha$ (usually 1):

$$P(x_i \mid y) = \frac{\text{count}(x_i, y) + \alpha}{\text{count}(y) + \alpha \cdot |V|}$$

**Work in log space.** Multiplying thousands of small probabilities underflows. Use sums of logs:

$$\hat{y} = \arg\max_y \left[ \log P(y) + \sum_i \log P(x_i \mid y) \right]$$

This also reveals that Naive Bayes is a **linear classifier** in log-space feature counts.

## Quick example

Spam filter, trained on 100 emails (40 spam, 60 ham). Say "free" appears in 30 spam, 3 ham; "meeting" in 1 spam, 25 ham. For an email containing both:

- Spam: $0.4 \times \frac{30}{40} \times \frac{1}{40} = 0.0075$
- Ham: $0.6 \times \frac{3}{60} \times \frac{25}{60} = 0.0125$

Ham wins. Note how a single very discriminative feature can dominate  a weakness when features are redundant (ten synonyms for "free" would each multiply in independently, as if they were ten pieces of evidence).

## Strengths

- **Extremely fast**  training is a single pass of counting; no iterative optimization
- **Works with tiny training sets**, since each parameter is estimated independently
- Handles high-dimensional data gracefully (text with 50k features is fine)
- Trivially supports **online/incremental learning**  just update counts
- Interpretable: you can inspect per-feature log-ratios

## Weaknesses

- Poorly **calibrated probabilities** (use Platt scaling or isotonic regression if you need real probabilities)
- Double-counts **correlated features**
- Can't learn feature **interactions** (e.g., XOR-type patterns)
- Gaussian NB is sensitive to non-normal continuous features  consider binning or power transforms
- Usually beaten by logistic regression, gradient boosting, or transformers given enough data

## When to reach for it

It's an excellent **baseline**: fit it in seconds before trying anything complex. It's genuinely competitive for text classification with limited labeled data, for real-time systems where latency matters, and as a component in larger pipelines. The NBSVM approach (Wang & Manning, 2012)  using NB log-count ratios as features for an SVM  was a strong text classification method for years and still makes a respectable baseline.

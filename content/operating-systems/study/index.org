* PART I — Computer Systems Overview

** Basic elements

A computer is /processor/ (CPU — controls operation, does data processing),
/main memory/ (stores data + programs; /volatile/; a.k.a. real/primary memory),
/I/O modules/ (move data to/from the outside), and a /system bus/ connecting them.
In RAM, one row is a /frame/ and the frame's length is a /word/.

CPU registers seen in the top-level view: /PC/ (program counter — address of the
next instruction), /IR/ (instruction register — the fetched instruction), /MAR/
(memory address register), /MBR/ (memory buffer register), and the I/O address /
buffer registers.

** Instruction cycle

Processing one instruction is an /instruction cycle/: /fetch/ then /execute/ (then
an /interrupt/ check). The processor fetches the instruction at the PC (which then
increments), loads it into the IR, and acts. Instruction actions fall into four
kinds: processor↔memory, processor↔I/O, /data processing/ (arithmetic/logic), and
/control/ (e.g. branch). The /opcode/ is the binary code identifying an
instruction.

** Interrupts

An /interrupt/ lets other modules (I/O, memory, timer) break the processor's
normal sequencing, to improve utilization (I/O is slow; the CPU shouldn't idle).
On an interrupt the user program is suspended, the /interrupt handler/ (part of
the OS) runs, then the suspended process resumes at the same point — the user
program needs no special code for this.

Four /types of interrupt/:
- /Program/: a condition from executing an instruction — overflow, divide by
  zero, illegal instruction, or a reference outside allowed memory.
- /Timer/: from a processor timer; lets the OS act at regular intervals.
- /I/O/: from an I/O controller — completion or error.
- /Hardware failure/: e.g. power failure or memory parity error.

To handle them an /interrupt stage/ is added to the cycle (fetch → execute →
interrupt check); if interrupts are disabled the stage is skipped.

** PSW and modes of operation

The /PSW/ (program status word) holds status about the running process: condition
codes, an interrupt enable/disable bit, and a /kernel/user-mode bit/. In /user
mode/ programs run with certain memory and instructions off-limits; in /kernel
mode/ (control mode) /privileged instructions/ run and protected memory is
accessible. This protects the OS and its tables from user programs.

** Evolution of operating systems

Serial processing (no OS) → /simple batch/ (a resident /monitor/ sequences jobs;
needs memory protection, timer, privileged instructions, interrupts) →
/multiprogrammed batch/ (run another job during I/O waits) → /time sharing/ (many
users at terminals; the OS interleaves short bursts called /quanta/). Batch
multiprogramming maximises /processor use/; time sharing maximises /response
time/.

** Memory hierarchy

Because faster and bigger both cost more, memory is layered: inboard (registers,
cache, main memory) → outboard (disk, optical) → offline (tape). Going /down/ the
hierarchy: cost per bit /decreases/, capacity /increases/, access time
/increases/, and frequency of processor access /decreases/. The goal is average
cost near the cheap level with average access time near the fast level.

*** Average cost per bit (from the notes)

For a two-level memory, /C_{s}/ is the average cost per bit:
\[ C_{s} = \frac{C_{1}S_{1} + C_{2}S_{2}}{S_{1}+S_{2}} \]
where $C_i$ is cost per bit and $S_i$ is size of level $i$. We want $C_{s}\approx
C_{2}$ (the cheaper level) while access time stays near the fast level.

** Cache memory and cache design

/Cache/ sits between the CPU and main memory and is largely invisible to the OS.
The processor accesses memory at least once per instruction cycle, so execution
speed is limited by memory cycle time; cache hides that latency.

/Cache design/ dimensions: cache size, /block size/, /mapping function/,
/replacement algorithm/, /write policy/, number of levels.
- /Block size/: larger blocks first raise the hit ratio (spatial /locality/) but
  too-large blocks evict useful data and hurt it — there is an optimal size.
- /Mapping function/ (where a block may sit): /direct/ (one fixed slot per block),
  /fully associative/ (any slot — flexible, fewer conflicts, but costly to
  search), /set associative/ (block maps to one set, any slot within it — the
  middle ground).
- /Replacement/: e.g. /LRU/ (least recently used).
- /Write policy/: write on every update, or /write back/ on replacement
  (fewer writes, but main memory is temporarily stale).

*** Hit ratio and average access time (standard formulas — not in your notes)

Your notes marked these =COME BACK LATER=; these are the standard textbook forms:
- /Hit ratio/ $H = \dfrac{\text{hits}}{\text{total accesses}}$; miss ratio $=1-H$.
- /Average (two-level) access time/, paying the fast level first and the slow
  level only on a miss:
  \[ T_{avg} = H\,T_{1} + (1-H)\,(T_{1}+T_{2}) = T_{1} + (1-H)\,T_{2} \]
  where $T_1$ = fast-level (cache) time, $T_2$ = slow-level (main memory) time.
  (Some texts write $T_{avg}=H T_1+(1-H)T_2$ if a miss does not re-pay $T_1$ —
  check which convention your slides use.)

** Principle of locality (standard — not in your notes)

Programs tend to reuse data and instructions near recent references — /temporal/
locality (same location again soon) and /spatial/ locality (nearby locations
soon). Locality is why caching and paging work.

* PART II — Memory Management

** Uniprogramming vs. multiprogramming

/Uniprogramming/: one program at a time, whole program loaded contiguously;
memory split into two parts (OS + the single user program). Wasteful: size capped
by memory, unused space wasted, CPU idle during I/O. /Multiprogramming/: divide
user memory among several processes so the CPU switches to another when one waits.
/Memory management/ decides how memory is allocated to and used by processes.

** The five memory-management requirements

*** Relocation

/Relocation/: load a program into any free part of memory and still address it
correctly. Needed because the programmer can't know the load location in advance
and a swapped-out process may return to a /different/ region. The processor
translates addresses at run time.

*** Protection

/Protection/: a process's memory can't be touched by others without permission.
Since location is unpredictable, references are checked at /run time/, and this
must be done by the /processor (hardware)/ — the OS can't anticipate every
reference. Mechanisms that support relocation also support protection.

*** Sharing

/Sharing/: let several processes access the same memory in a controlled way (e.g.
one copy of a shared program) without breaking protection.

*** Logical organization

/Logical organization/: structure memory as /modules/ (code, data, stack) to allow
independent compilation, per-module protection, and module-level sharing.
/Segmentation/ supports this best.

*** Physical organization

/Physical organization/: manage the two-level memory (fast volatile main vs. slow
cheap non-volatile secondary) and the flow between them. This should be a /system/
responsibility, not the programmer's (main memory may be too small; the programmer
can't know available space at coding time).

** Types of addresses

- /Physical/ (absolute): the actual main-memory location.
- /Logical/: a reference independent of the current data-to-memory assignment.
- /Relative/: a logical address expressed relative to a known point (program
  origin). Hardware translates relative → physical using the /base register/
  (start) and /bounds register/ (end, which also enforces protection).

** Fixed partitioning

/Fixed partitioning/: memory split into /static/ partitions at system-generation
time; a process loads into an equal-or-larger partition. Simple, low overhead, but
suffers /internal fragmentation/ (a process smaller than its partition wastes the
rest), wastes memory, and caps the number of active processes. Equal-size
placement is trivial; for /unequal-size/ assign a process to the /smallest/
partition that fits. Programs bigger than a partition need /overlays/.

** Dynamic partitioning

/Dynamic partitioning/: variable-size partitions, each exactly the size a process
needs. Removes internal fragmentation but causes /external fragmentation/ (small
holes between allocations). Fixed by /compaction/ (shift processes together to
merge holes). Relocation is /always/ required (swap-in and compaction move
processes).

*** Placement algorithms

- /Best-fit/: the free block closest in size to the request.
- /First-fit/: the first hole from the start that fits (leaves small holes early,
  forcing compaction sooner).
- /Next-fit/: the next hole that fits, scanning from the last placement (wraps
  around).

** Paging

/Paging/: memory in equal fixed-size /frames/, a process in equal /pages/ of the
same size; pages load into any free frames — /need not be contiguous/, which kills
external fragmentation. Waste is only internal fragmentation, at most a fraction
of the /last page/. Paging is /transparent/ to the programmer; with a power-of-2
page size the logical address equals the relative address, and the physical
address is formed by /appending/ the frame number to the offset.

The OS keeps one /page table/ per process mapping /page number → frame number/.

** Segmentation

/Segmentation/: a process split into /segments/ that vary in length (up to a
maximum), matching logical modules. Address = (segment number, offset), resolved
via a /segment table/ storing each segment's base and length. It is /visible/ to
the programmer, /eliminates internal/ fragmentation, but suffers /external/
fragmentation.

** Combined paging + segmentation

Split the space into /segments/, then split each segment into /pages/. Translation
is two-level (segment table → that segment's page table → frame). Combines paging's
efficiency with segmentation's modularity/sharing/protection, at the cost of
/complex overhead/ (two tables, two lookups). This is why plain paging is usually
preferred.

** Virtual memory

/Virtual memory/ uses disk as if it were main memory, giving the illusion of more
memory. The part of a process resident in memory is its /resident set/. A
reference to a non-resident page triggers a /page fault/; the OS reads that page
in. Benefits: more processes resident (better CPU use), and a process may be
/larger than all of main memory/.

*** Thrashing and locality

/Thrashing/: the OS spends most of its time swapping instead of executing —
happens when it evicts a piece just before it is needed. Avoided by guessing, from
recent history, which pieces are /least/ likely to be used soon. This works
because of the /principle of locality/ (references cluster over short periods).

*** Page-fault rate vs. page size

As page size grows (fixed frames), the fault rate first /rises/ then /falls/: tiny
pages keep lots of locality resident (low faults); bigger pages hold locations
further from recent references (locality diluted, faults rise); very large pages
approach the whole process, and when one page spans it there are no faults.

** Page tables at scale

A flat page table's size grows with the address space. Example: 32-bit address,
byte addressing, 4 KB = $2^{12}$-byte pages, 4-byte entries → $2^{32}/2^{12} =
2^{20}$ pages → $2^{20}\times4 = 4$ MB per process (400 MB for 100 processes).
Solutions:
- /Two-level page table/: page the page table; a small /root/ table stays resident
  and the rest lives in virtual memory.
- /Inverted page table/: one entry per real /frame/ (sized by physical memory),
  indexed by a /hash/ of the virtual page number.
- /TLB/ (translation lookaside buffer): a fast cache of recent page-table entries;
  on a /TLB hit/ the frame number is read directly, avoiding a page-table walk.

* PART III — Process Management

** Program vs. process

A /program/ is passive (a file, instructions); a /process/ is a program brought to
life — an instance running (user view), an entity schedulable on a processor
(scheduler view), or a unit of activity with instructions + current state +
resources (implementer view).

** Process elements and the PCB

A process is characterised by: identifier, state, priority, program counter,
memory pointers, context data, I/O status, accounting info. The OS stores these
per process in a /process control block/ (PCB). When a process is interrupted, its
PC and registers (/context/) are saved to the PCB, its state changes (e.g. to
ready/blocked), and another process can run.

The PCB groups info into three categories: /process identification/ (this PID,
parent PID, user id), /processor state information/ (user-visible registers,
control/status registers, /PSW/, stack pointers), and /process control
information/ (state, priority, scheduling info, the /event/ awaited, memory
pointers, privileges, resources).

** Process image

The /process image/ = /user program/ + /user data/ + /stack/ (LIFO, for call
parameters and return addresses) + /PCB/. Under simple schemes the image is a
contiguous block that must be fully in memory to run; under virtual memory only
part need be resident.

** Trace and dispatcher

A /trace/ is the sequence of instructions a single process executes. The
processor's behaviour is the /interleaving/ of process traces. The /dispatcher/ is
a small program that switches the processor from one process to another.

** Two-state model

Simplest model: a process is /Running/ or /Not Running/; a queue feeds the
dispatcher. Limitation: "Not Running" hides two cases — /ready/ vs. /blocked/
(waiting on an event) — so with one queue the dispatcher may have to search for a
runnable process. Hence a richer model is needed.

** Five-state model

States: /New/, /Ready/, /Running/, /Blocked/, /Exit/.

Key transitions: /New→Ready/ (OS admits it), /Ready→Running/ (dispatch),
/Running→Ready/ (timeout / preemption), /Running→Blocked/ (waits on I/O, a system
call, or IPC), /Blocked→Ready/ (the awaited event occurs), /Running→Exit/
(completes or aborts).

** Queuing model

One blocked queue is simple but forces the OS to scan the whole queue when an event
occurs. The refinement: a /ready queue/ plus /one blocked queue per event/.

** Suspended processes and swapping

/Swapping/ moves part or all of a process out to disk (a /suspend queue/) when no
resident process is Ready. This adds /suspend/ states — split into /Ready/Suspend/
and /Blocked/Suspend/ (a suspended process may or may not still be waiting on an
event). A suspended process is not available to run until the agent (itself, a
parent, or the OS) explicitly releases it. Reasons to suspend: swapping, other OS
need, interactive user request, timing, parent request.

** OS control tables

Four linked table groups: /memory tables/ (real + virtual memory allocation,
protection, VM info), /I/O tables/ (device status, buffers), /file tables/ (file
existence, location, status), and the /process table/ (the PCBs). They must
cross-reference one another.

** Modes of execution and the kernel

/User mode/ (less privileged, for user programs) vs. /system/kernel mode/ (more
privileged, runs the /kernel/ — the core of the OS — with privileged
instructions). This protects OS tables (PCBs, page tables). The PSW's mode bit
flips to kernel mode on a system call or interrupt, and back (via an interrupt
return, IRT) on return. x86 has 4 rings: ring 0 = kernel, ring 3 = user.

Typical /kernel functions/: process management (creation/termination,
scheduling/dispatching, switching, synchronization/IPC, PCB management), memory
management, I/O management, and support (interrupt handling, accounting,
monitoring).

** Process creation

To create a process the OS: (1) assigns a unique /PID/, (2) allocates space, (3)
initialises the /PCB/, (4) sets linkages, (5) creates/expands other data
structures. Causes: new batch job, interactive log-on, created by the OS for a
service, or /spawned/ by an existing process (giving a /parent/ and /child/).

** Interrupting a process: interrupt vs. trap vs. supervisor call

- /Interrupt/: /external/ to the current instruction; an asynchronous event
  (clock, I/O, memory fault).
- /Trap/: /associated/ with the current instruction; an error/exception in the
  running process (the OS decides if it is fatal).
- /Supervisor call/: an /explicit/ request — a call to an OS function.

A /time slice/ is the max time a process runs before being interrupted.

** Mode switch vs. process switch

A /mode switch/ (user↔kernel, e.g. to run an interrupt handler) is cheaper than a
/process switch/. To change the running process the OS: (1) saves the processor
context, (2) updates the current process's PCB, (3) moves that PCB to the right
queue, (4) selects another process, (5) updates its PCB, (6) updates memory-
management structures, (7) restores the selected process's context.
